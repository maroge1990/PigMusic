| 30 Oct 2026 | LOOP1 batch B (d093295, 7c9f33f), Codex round 2 | Medium | `Auth.authenticate` renews a session's `last_seen_at`/`expires_at` with a synchronous UPDATE once an hour, and it now runs on the 4 reserved `SESSION_THREADS`. `Store.connect` lets a write wait up to 10 s behind another writer, so four requests renewing at once while the database is busy can occupy every reserved thread and queue all sign-in checks (including login's `auth.ready`). Before 7c9f33f the same work shared the 10-worker default pool with everything else (28 Oct live: 1.8 s in auth-ready with that pool full). Reproduced by Codex in memory with paused renewal UPDATEs; the real SQLite-writer case follows from the code but was not run. Recorded for later by the owner (30 Oct). Fix direction: validate on the reserved threads and schedule renewal writes separately, deduplicated per session, preserving expiry and revocation; regression holding a disposable WAL writer while four stale sessions renew and asserting a fresh session's check stays responsive | `server/auth.py` `Auth.authenticate`; `server/security.py` `SESSION_THREADS`, `Security.current_user` |
